# Context

Claude Code는 `CLAUDE.md`, Gemini CLI는 기본적으로 `GEMINI.md`, Codex는 `AGENTS.md`를 사용한다. 세 파일에 동일한 팀 규칙을 복사하면 시간이 지나면서 서로 다른 내용이 된다.

Claude Code는 `CLAUDE.md`에서 `@AGENTS.md`를 import하는 방식을 공식 안내하며, Gemini CLI도 `@file` import를 지원한다.[^claude-memory][^gemini-context] Codex는 `AGENTS.md`를 직접 계층적으로 탐색한다.[^codex-agents]

# Decision

1. 루트 `AGENTS.md`를 도구 중립 공용 지침의 단일 원본으로 둔다.
2. `CLAUDE.md`는 `@AGENTS.md` 뒤에 Claude 전용 차이만 둔다.
3. `GEMINI.md`는 `@./AGENTS.md` 뒤에 Gemini 전용 차이만 둔다.
4. Codex에는 루트 `AGENTS.md` 외의 중복 지침 파일을 만들지 않는다.
5. 실행 권한은 자연어 지침이 아니라 각 제품 설정과 조직 정책으로 별도 시행한다.

# Consequences

## Benefits

- 공용 규칙을 한 번만 수정한다.
- 제품별 차이와 팀 규칙을 쉽게 구분한다.
- 리뷰에서 어댑터가 공용 규칙을 복제했는지 발견하기 쉽다.

## Costs

- import와 자동 탐색을 지원하지 않는 새 도구는 별도 어댑터가 필요하다.
- 제품별 로딩 상태를 각 CLI의 진단 명령으로 확인해야 한다.
- 공용 Skill은 실행 경로 사본이 필요하므로 자동 drift 검사가 필요하다.

# Alternatives

- **세 파일에 전체 규칙 복사**: 처음은 단순하지만 drift 위험 때문에 채택하지 않는다.
- **symlink로 모든 파일 통일**: Windows 권한과 제품별 차이 추가가 불편하여 채택하지 않는다.
- **Plugin 하나로만 배포**: 제품별 패키지 형식이 달라 저장소 규칙의 단일 배포 수단이 될 수 없어 채택하지 않는다.
